# 06: Закрытие записи

Status: ready-for-agent
State: closed

**Source:** [MVP сервиса бронирования звонков](../../booking-mvp/spec.md).

**What to build:** владелец окончательно снимает публикацию типа встречи.
Гости больше не могут записаться по нему, а созданные встречи сохраняются
в списке владельца и продолжают занимать время для всех типов.

**Blocked by:** 04: [«Подтверждение встречи»](04-confirm-meeting.md).

- [x] Владелец снимает публикацию опубликованного типа через согласованное действие интерфейса; состояние сохраняется и отражается после перезагрузки.
- [x] Снятый с публикации тип не возвращается в черновик и не публикуется повторно. Новый тип с тем же названием получает отдельную ссылку, старые ссылки автоматически на него не переключаются.
- [x] Подтверждение с уже открытого экрана после снятия публикации не создаёт встречу и показывает «Запись на этот тип встречи закрыта»; отображение каталога и прямой ссылки соответствует итоговой спецификации.
- [x] Все существующие встречи сохраняются, предстоящие отображаются владельцу, занятое ими время исключается из слотов других типов.
- [x] Снятие публикации согласовано с проверкой состояния и сохранением встречи: если первой сохранена встреча, она остаётся; если первой снята публикация, новая встреча не создаётся.
- [x] Переход состояния и ошибки отражены в OpenAPI-контракте, типы обеих сторон обновлены генерацией, правила проверяются на бэкенде.
- [x] Браузерные проверки охватывают закрытие записи владельцем, отказ гостю со старого экрана и сохранение встречи и занятости. HTTP-проверки контролируют оба порядка конкурентных действий и запрет обратных переходов.
- [x] Экран сохраняет согласованный стиль и мобильную доступность; `mise run check` проходит, Go-тесты выполняются с `-race`.

## Comments

### 2026-11-15 — запуск шестого среза

Пользователь запросил `implement-spec 06` после закрытия задач 04 и 05.
Жизненный цикл согласован в решении карты 01: снятие окончательно,
встречи и занятость сохраняются, новый запрос после снятия отклоняется
с сообщением «Запись на этот тип встречи закрыта». Новый одноимённый тип
имеет отдельный ID и ссылку. Общий блокер обзора карты снят только
для этой задачи; удаление и Docker остаются задачами 07 и 08.

Технический контракт данного среза:

- `POST /api/owner/meeting-types/{meetingTypeId}/withdraw`
  (`withdrawOwnerMeetingType`), без тела: опубликованный → `withdrawn`,
  HTTP 200 с типом. Повтор для `withdrawn` возвращает тот же тип.
  Черновик — HTTP 409 без изменения, неизвестный тип — HTTP 404.
- `publishOwnerMeetingType` для `withdrawn` возвращает HTTP 409;
  существующая идемпотентность публикации для опубликованного типа сохраняется.
- Каталог показывает только опубликованные типы. Прямое чтение типа,
  чтение слотов и новая попытка подтверждения по `withdrawn` возвращают
  HTTP 410 с точным согласованным сообщением. Черновик/неизвестный ID
  остаются HTTP 404. Закрытая ссылка не переходит на одноимённый новый тип.
- Снятие публикации, проверка состояния и сохранение встречи используют
  одну критическую секцию календаря. Сохранённая первой встреча остаётся;
  снятие первым запрещает создание новой.
- Успешная попытка из задачи 05 продолжает возвращать исходную встречу
  после закрытия: lookup/сопоставление выполняются до проверки публикации,
  не создают новую встречу и не раскрывают результат при изменённых данных.
- В `/owner` у опубликованного типа действие «Снять публикацию»
  с пояснением окончательности; после успеха — состояние «Снят с публикации»
  без действия повторной публикации. Гость видит закрытие на прямой ссылке,
  при обновлении слотов или при подтверждении старого выбора.

Границы проверок прежние: HTTP с управляемым временем и браузер с настоящим
API. Поведение подтверждения/повтора из задачи 05 сохраняется,
контакты не добавляются в публичные ответы о закрытии.

## Answer

Реализовано в `codex/booking-draft-integration`, коммит `a73d492`
(`Close booking after publication withdrawal`).

- Добавлено состояние `withdrawn` и `withdrawOwnerMeetingType`.
  Опубликованный тип окончательно закрывается; повтор снятия возвращает
  тот же тип. Черновик не меняется (HTTP 409), неизвестный ID — HTTP 404.
  Повторная публикация закрытого типа запрещена HTTP 409.
- В `/owner` есть «Снять публикацию» с пояснением окончательности
  и сохранения встреч; ошибка сети допускает повтор. После успеха
  карточка показывает «Снят с публикации» без обратного действия,
  в том числе после перезагрузки.
- Каталог исключает закрытый тип. Прямое чтение, слоты и новая попытка
  подтверждения возвращают HTTP 410: «Запись на этот тип встречи закрыта».
  Черновик/неизвестный ID сохраняют HTTP 404. Старые ссылки не переводятся
  на новый одноимённый тип. Интерфейс прямой ссылки и старого выбранного
  слота показывает закрытие без элементов дальнейшей записи.
- Все встречи сохраняются, будущие/идущие отображаются владельцу;
  их интервалы исключаются из доступности всех типов. Снятие публикации
  и проверка состояния с сохранением встречи выполняются под одним mutex.
  Сохранённая первой встреча остаётся; снятие первым запрещает новую.
- Повтор успешной попытки из задачи 05 возвращает исходную полную встречу
  с прежними ID и ссылкой после снятия публикации, включая прошедшую
  встречу. Изменённый email/имя/интервал с прежним UUID не раскрывает
  старое подтверждение. Новая попытка закрытого типа не сохраняется.
  Запаздывающий ответ слотов о закрытии не подменяет результат
  ожидающей/неизвестной попытки и не сбрасывает успешное подтверждение.
- Контракт изменён первым, Go/TypeScript обновлены генерацией.
  Новых зависимостей, маршрутов тестового времени/reset, удаления
  или Docker в этом срезе не добавлено. README синхронизирован.
