# 07: Удаление типа

Status: ready-for-agent
State: closed

**Source:** [MVP сервиса бронирования звонков](../../booking-mvp/spec.md).

**What to build:** владелец удаляет ненужный тип встречи в любом состоянии,
если по нему нет ни одной встречи. Тип с будущими или прошедшими встречами
удалить нельзя; запись по ссылке удалённого типа невозможна.

**Blocked by:** 06: [«Закрытие записи»](06-close-booking.md).

- [x] Владелец может удалить черновик, опубликованный и снятый с публикации тип без встреч; тип исчезает из соответствующих списков и не возвращается после перезагрузки.
- [x] Наличие любой встречи, включая прошедшую, запрещает удаление; интерфейс сообщает согласованную причину. Для опубликованного типа остаётся доступным снятие публикации.
- [x] Прямая ссылка и уже открытый экран удалённого типа не позволяют создать встречу; одноимённый новый тип не становится автоматической заменой.
- [x] Проверка отсутствия встреч и удаление согласованы с бронированием: сохранённая первой встреча запрещает удаление, удалённый первым тип запрещает бронирование. Встречи с исчезнувшим типом не возникают.
- [x] Контракт, ответы об ошибках и генерируемые типы обновлены; сервер запрещает обход ограничений прямым запросом.
- [x] Браузерные проверки охватывают удаление во всех состояниях, отказ при наличии встречи и старую ссылку. HTTP-проверки охватывают будущие и прошедшие встречи и оба порядка конкурентных действий с бронированием.
- [x] Экран сохраняет согласованный стиль и мобильную доступность; `mise run check` проходит, Go-тесты выполняются с `-race`.

Пользователь запросил `implement-spec 07` после завершения задачи 06.
Удаление согласовано в решении карты 01: любое состояние допускает удаление
только при отсутствии всех встреч, включая прошедшие. Общий блокер обзора
карты снят только для этой задачи; Docker остаётся задачей 08.

Технический контракт среза: `DELETE /api/owner/meeting-types/{meetingTypeId}`
(`deleteOwnerMeetingType`), без тела. Успех — HTTP 204; неизвестный или уже
удалённый ID — HTTP 404. Любая встреча запрещает удаление: HTTP 409,
«Нельзя удалить тип встречи, по которому есть встречи»; для опубликованного
типа доступно снятие публикации. Проверка всех встреч и удаление происходят
под тем же mutex, что подтверждение. Сохранённая первой встреча сохраняет тип;
удалённый первым тип запрещает новое подтверждение (HTTP 404).

В `/owner` действие «Удалить» доступно в каждом состоянии, с пояснением
ограничения; успешный ответ убирает карточку, ошибка допускает повтор.
HTTP 404 после потерянного успешного ответа также убирает устаревшую карточку.
Старый гостевой экран и прямая ссылка остаются привязаны к ID и сообщают
недоступность, без замены новым одноимённым типом. Повторы сохранённых
успешных попыток и изоляция гостей из задачи 05 сохраняются.

Границы TDD прежние, ранее согласованные: публичный HTTP через
`server.NewWithClock` и Playwright с настоящим API. Новых границ,
постоянного хранения, отмены встреч или Docker этот срез не добавляет.

## Answer

Реализовано на `codex/booking-draft-integration`: `4a29ee7`
(`Delete meeting types without meetings`), правка одной устаревшей фразы
README — `e2c40b6` (`Update remaining MVP task`).

- Добавлен `deleteOwnerMeetingType`: DELETE без тела, HTTP 204 при успехе,
  HTTP 404 для неизвестного/уже удалённого ID, HTTP 409 с причиной
  «Нельзя удалить тип встречи, по которому есть встречи» при любой встрече,
  включая прошедшую. Контракт изменён первым; Go и TypeScript сгенерированы.
  Реальный ответ 409 проверяется по HTTP-опубликованному OpenAPI.
- Владелец удаляет черновик, опубликованный и снятый с публикации тип.
  Ограничение объяснено у действия; есть ожидание, ошибка и повтор.
  Карточка исчезает после 204 или повторного 404 после потери успешного ответа.
  Запоздалые ответы списка/публикации/снятия не возвращают удалённый тип
  и не подменяют результат. При запрете карточка остаётся с причиной;
  опубликованный тип можно снять с публикации.
- Проверка всех сохранённых встреч и удаление выполняются под общим mutex
  календаря с подтверждением. Сохранённая первой встреча запрещает удаление;
  удалённый первым тип запрещает новую встречу. Связь с типом, общая занятость
  и успешные повторы, включая прошлые встречи, сохраняются. Изменённый email
  с прежним UUID не раскрывает старое подтверждение.
- Прямая ссылка удалённого ID недоступна; старый открытый выбор при обновлении
  или подтверждении показывает недоступность без формы, даты и действий записи.
  Новый одноимённый тип имеет отдельный ID и не заменяет старую ссылку.
  Поздний 404 слотов не прерывает неизвестную попытку: повтор сохраняет тот же
  запрос и доводит его до определённого ответа.
- Новых зависимостей, внешнего хранения, отмены встреч, тестовых reset/clock
  маршрутов или Docker не добавлено. README обновлён.

TDD выполнен на ранее согласованных публичных границах HTTP с управляемым
временем и Playwright с настоящим API. Зафиксированы красные/зелёные циклы
для отсутствующего обработчика DELETE, пропущенного запрета при встрече,
действия владельца, терминального старого экрана и запоздалой публикации.
HTTP-проверки покрывают все состояния, будущую/идущую/прошедшую встречу,
повторы/приватность, оба последовательных порядка и 40 конкурентных пар
удаление/подтверждение без исчезнувшего типа у сохранённой встречи.
