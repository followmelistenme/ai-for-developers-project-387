## Question

Каковы данные и жизненный цикл типа встречи от создания до публикации,
и какие изменения доступны владельцу после публикации и появления встреч?

Зафиксировать обязательность и ограничения названия, описания и длительности;
допустимые длительности; начальное состояние и публикацию. Решить, нужны ли
редактирование, снятие публикации и удаление, и как выбранные действия влияют
на уже созданные встречи и открытый гостем экран записи.

Определить, стартует ли приложение без типов встреч или с примерами,
и какое состояние получает владелец после перезапуска хранилища в памяти.
Не менять заданные рабочие часы, окно записи и шаг стартов.

Результат — согласованные состояния, допустимые действия и примеры
поведения при изменении типа с будущей встречей. Не реализовывать CRUD.

## Comments

### 2026-11-15 — согласован первый раунд

- Название обязательно: 1–100 символов после обрезки пробелов по краям.
  Одинаковые названия разрешены.
- Описание необязательно: обычный текст длиной до 500 символов.
- Допустимые длительности: 15, 30, 45 и 60 минут.
  Шаг стартов остаётся 30 минут независимо от длительности.
- Сохранение заполненной формы создаёт черновик. Отдельное действие
  «Опубликовать» открывает запись гостям. Черновики гостям недоступны.
- При запуске приложение не содержит типов встреч и встреч, примеры
  автоматически не создаются. После перезапуска бэкенда состояние снова
  пустое; владельцу предлагается создать первый тип встречи.
- Открыты правила редактирования, снятия публикации, удаления и поведения
  уже открытого гостем экрана записи при изменении типа встречи.

### 2026-11-15 — согласован второй раунд

- Редактирование сохранённых типов встреч не разрешено.
- Снятие публикации разрешено и окончательно: тип не возвращается
  в черновик, повторно опубликовать его нельзя. Чтобы снова открыть запись,
  владелец создаёт новый тип встречи.
- Удалить тип встречи можно только при отсутствии любых встреч по нему,
  включая прошедшие. При наличии встреч доступно снятие публикации.
- Предложение о редактировании с сохранением прежних данных встречи
  и предложение о возврате в черновик с повторной публикацией отклонены.
- Осталось согласовать сохранение существующих встреч после снятия
  публикации и подтверждение записи с уже открытого экрана.

### 2026-11-15 — согласован третий раунд

- Снятие публикации не отменяет существующие встречи: они сохраняются,
  отображаются владельцу и продолжают занимать время для всех типов встреч.
- Подтверждение с уже открытого экрана после снятия публикации отклоняется
  с сообщением «Запись на этот тип встречи закрыта».
- Новый тип, даже с тем же названием, получает отдельную ссылку.
  Старый экран записи автоматически на него не переключается.
- При одновременном подтверждении и снятии публикации решает порядок
  сохранения: сохранённая первой встреча остаётся; после снятия публикации
  новые встречи не создаются.

## Answer

Итог согласован по ответам трёх раундов и целиком подтверждён пользователем

### Данные типа встречи

| Поле | Правило |
| --- | --- |
| Название | Обязательно, 1–100 символов после обрезки пробелов по краям; одинаковые названия разрешены |
| Описание | Необязательно, обычный текст до 500 символов |
| Длительность | Одно из значений: 15, 30, 45, 60 минут |

Ограничения проверяются при создании типа встречи на бэкенде.
Сохранение заполненной корректной формы создаёт черновик.
Сохранённые данные не редактируются ни в одном состоянии: для исправления
или изменения данных нужно создать новый тип встречи.

### Состояния и действия

Основной путь: **Черновик → Опубликован → Снят с публикации**.
Обратных переходов нет.

| Состояние | Доступность гостю | Действия владельца |
| --- | --- | --- |
| Черновик | Просмотр и запись недоступны | Опубликовать, удалить |
| Опубликован | Просмотр и запись доступны | Снять публикацию; удалить, если нет встреч |
| Снят с публикации | Новая запись недоступна | Удалить, если нет встреч |

Публикация — отдельное действие. Снятие публикации окончательно:
тип не становится черновиком и не может быть опубликован повторно.
Для возобновления записи создаётся новый тип с отдельной ссылкой,
даже если название совпадает. Старые ссылки не перенаправляют на новый тип.

Окончательное удаление допустимо из любого состояния только при отсутствии
любых встреч по типу, включая прошедшие. При наличии встреч удаление
запрещено; опубликованный тип можно снять с публикации.
Снятие публикации сохраняет все встречи и их занятое время.

### Открытый экран записи и одновременные действия

Открытие экрана и выбор слота не гарантируют создание встречи.
При подтверждении бэкенд проверяет, что тип существует и опубликован,
вместе с остальными правилами бронирования.

Если публикация уже снята, новая встреча не создаётся; гость получает
сообщение «Запись на этот тип встречи закрыта». Если тип удалён, запись
по старой ссылке также невозможна. Автоматического переключения на другой
тип, в том числе с тем же названием, нет.

Проверка состояния типа и сохранение встречи согласованы со снятием
публикации: если встреча сохранена первой, она остаётся; если первой снята
публикация, подтверждение отклоняется. Проверка отсутствия встреч
и удаление также не должны допускать удаления типа, по которому
одновременно успела сохраниться встреча.

HTTP-статусы, структура ошибок и повторные запросы уточняются
в [задаче о семантике API](06-api-semantics.md)
и [задаче о повторном подтверждении](03-booking-retries.md).
Представление этих состояний уточняется в задачах
[об интерфейсе владельца](04-owner-experience.md)
и [пути гостя](05-guest-experience.md).

### Примеры поведения

1. По типу «Знакомство», 30 минут, создана встреча на завтра 10:00–10:30.
   Изменить тип на 60 минут нельзя. Владелец снимает публикацию и создаёт
   новый тип на 60 минут. Прежняя встреча остаётся в списке владельца;
   занятость 10:00–10:30 учитывается при расчёте слотов нового типа.
2. Гость выбрал слот, владелец снял публикацию, затем гость подтвердил
   запись. Подтверждение отклоняется, встреча не создаётся.
3. Гость успел сохранить встречу до снятия публикации. Встреча остаётся
   действующей после снятия публикации; удалить её тип нельзя.
4. Черновик содержит ошибку в названии. Исправить сохранённый черновик
   нельзя; владелец удаляет его и создаёт новый.
5. У опубликованного типа нет встреч. Владелец может удалить его;
   запись по ранее открытой ссылке становится невозможной.

### Запуск и перезапуск

Приложение запускается без типов встреч и встреч; примеры автоматически
не создаются. Владельцу предлагается создать первый тип встречи.
Перезапуск бэкенда очищает данные в памяти: все типы и встречи исчезают,
старые ссылки больше не позволяют записаться на прежние типы.

Рабочие часы, окно записи, московский часовой пояс, шаг стартов 30 минут
и правила пересечений сохраняются без изменений. CRUD, контракт API
и интерфейс в рамках этой задачи не реализуются.
