# 02: Публикация и выбор типа

Status: ready-for-agent
State: closed

**Source:** [MVP сервиса бронирования звонков](../../booking-mvp/spec.md).

**What to build:** владелец публикует черновик отдельным действием,
а гость переходит с главной, выбирает опубликованный тип встречи
и открывает его отдельную ссылку.

**Blocked by:** 01: [«Создание черновика»](01-create-draft.md) — завершена.

## Границы второго среза

- Пользователь запросил реализацию этой задачи после завершения первого
  среза. Полное согласование остального MVP не блокирует публикацию
  и выбор типа; открытые решения карты не считаются разрешёнными.
- Каталог опубликованных типов — `/booking`, отдельная страница типа —
  `/booking/{meetingTypeId}`. Идентификатор типа отличается от идентификатора
  созданной встречи в демонстрационной ссылке для звонка.
- Техническое расширение контракта: `POST /api/owner/meeting-types/{meetingTypeId}/publish`
  без тела запроса; `GET /api/meeting-types` и
  `GET /api/meeting-types/{meetingTypeId}` для опубликованных типов.
  Публикация возвращает HTTP 200 с типом; повторная публикация уже
  опубликованного типа возвращает его без дублирования. Неизвестный тип,
  а в гостевом API также черновик, возвращают HTTP 404.
- Проверки остаются на существующих границах HTTP API и Playwright
  с настоящим сервером. Названия, описания и длительности не редактируются.

- [x] Владелец публикует созданный черновик; состояние сохраняется в пределах текущего процесса и отображается после перезагрузки страницы.
- [x] Обе кнопки записи с главной открывают выбор опубликованного типа встречи; временная заглушка заменена соответствующим согласованным экраном.
- [x] Гость видит название, длительность и описание, если оно задано; при отсутствии опубликованных типов показано согласованное пустое состояние.
- [x] Каждый тип имеет отдельную ссылку, включая типы с одинаковыми названиями. Прямое открытие и перезагрузка ссылки работают.
- [x] Черновики недоступны гостю через интерфейс и прямые запросы к публичному API; публикация не разрешает редактировать сохранённые данные.
- [x] Публичный интерфейс не предлагает подтверждать ещё не реализованную запись; следующие шаги добавляются зависимыми задачами.
- [x] Контракт расширен до реализации операций, типы обеих сторон обновлены генерацией, входные данные проверяются на бэкенде; ошибки и загрузка представлены согласно итоговой спецификации.
- [x] Браузерный сценарий проверяет создание → публикацию → выбор гостем и прямую ссылку; HTTP-проверки подтверждают видимость опубликованного типа и недоступность черновика.
- [x] Экран сохраняет согласованный стиль, доступность и мобильную адаптацию; `mise run check` проходит, включая проверку актуальности генерации.

## Answer

Реализовано в `0ab0ba3` (`Publish meeting types and add guest catalogue`),
слито в `codex/booking-draft-integration`.

- Владелец публикует черновик отдельным действием; статус и ссылка
  опубликованного типа доступны после перезагрузки страницы.
- Гость получает каталог `/booking` и отдельную страницу
  `/booking/{meetingTypeId}`. Название, описание и длительность сохраняются;
  одинаковые названия имеют разные ссылки. Черновик и неизвестный тип
  недоступны в гостевом API и интерфейсе.
- Публикация, фильтрация и чтение защищены общей блокировкой хранилища.
  Повтор и конкурентные публикации не создают дубликатов.
- Сначала расширен OpenAPI-контракт, затем сгенерированы обе стороны.
  Middleware учитывает наличие тела в контракте: публикация работает
  без тела, а создание сохраняет строгую проверку JSON и ограничений.
- Каталог и отдельная страница имеют загрузку, пустое состояние,
  недоступность типа и повтор после сетевого сбоя. Слот и подтверждение
  не предлагаются до следующих срезов.

TDD: HTTP-сценарий и браузерная публикация сначала падали, затем прошли.
Случай `/booking/` воспроизведён отдельным падающим тестом и исправлен;
вложенные некорректные ссылки недоступны. Браузерные сценарии используют
отдельный настоящий API-процесс на каждый тест, без производственного
reset-эндпоинта и зависимости от порядка сценариев.

Итоговый `mise run check` в основной рабочей папке прошёл: 12 браузерных
сценариев, Go `-race`, линтеры, форматирование, актуальность генерации,
модули, проверка достижимых уязвимостей, сборка и типизация, workflow,
инструкции и секреты. Ревью Standards: 0 замечаний. Ревью Spec: 0 замечаний.
Каталог, отдельная страница и управление проверены визуально
на компьютере и на ширинах 320 и 390 px.
