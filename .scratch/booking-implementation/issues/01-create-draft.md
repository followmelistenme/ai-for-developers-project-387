# 01: Создание черновика

Status: ready-for-agent
State: closed

**Source:** [MVP сервиса бронирования звонков](../../booking-mvp/spec.md).

**What to build:** владелец календаря открывает управление, создаёт тип
встречи и видит сохранённый черновик. Сервис запускается локально с пустыми
данными и предлагает создать первый тип встречи.

**Blocked by:** None (can start immediately).

## Согласованный первый срез

- Управление доступно по `/owner`; в шапке ссылка «Для владельца».
  На странице список типов встреч и кнопка «Создать тип встречи»;
  пустое состояние предлагает создать первый тип. Авторизации нет.
- `GET /api/owner/meeting-types` возвращает список, в том числе пустой.
- `POST /api/owner/meeting-types` принимает название, необязательное описание
  и длительность в минутах. Сервер назначает уникальный идентификатор
  и состояние `draft`, возвращает созданный тип с HTTP 201.
- При ошибке данных HTTP 400 содержит сообщение и ошибки по полям.
- Проверки на согласованных границах: Playwright с настоящим API
  для пользовательского сценария и HTTP API для ограничений и сброса данных.
- Пользователь подтвердил оба уточнения и переход к реализации первой
  задачи без ожидания полного согласования MVP. Остальные задачи карты
  не считаются разрешёнными.

- [x] Владелец попадает в управление согласованным для первого среза способом: `/owner` и ссылка «Для владельца»; пустое состояние предлагает создать первый тип встречи.
- [x] Форма создаёт черновик и показывает его владельцу после сохранения и перезагрузки страницы; регистрация и авторизация не добавляются.
- [x] Бэкенд проверяет название длиной 1–100 символов после обрезки пробелов по краям, необязательное описание обычным текстом до 500 символов и длительность 15, 30, 45 или 60 минут. Одинаковые названия разрешены.
- [x] Некорректные данные не сохраняются; гостевые экраны и маршруты записи не предоставляют черновики. Управление владельца доступно без авторизации, как согласовано. Редактирование сохранённого типа не предоставляется.
- [x] Данные хранятся только в памяти, защищённой от конкурентного доступа; запуск и перезапуск бэкенда дают пустое состояние без примеров.
- [x] Сценарий работает через OpenAPI-контракт и сгенерированные DTO обеих сторон: Gin и oapi-codegen с models, gin-server, strict-server, embedded-spec; openapi-typescript и openapi-fetch на клиенте. Схемы именованы, operationId стабильны; HTTP-валидация подключена отдельно.
- [x] Версии генераторов закреплены, сгенерированные результаты хранятся в Git, CI проверяет их актуальность. Доступны обе формы OpenAPI и документация API согласно спецификации.
- [x] Фронтенд и бэкенд совместно запускаются локально с настройкой портов и адреса API через окружение; команды и переменные документированы.
- [x] Новый экран русскоязычный, сохраняет тёмную палитру с синим акцентом и доступен на телефоне; существующая главная продолжает работать.
- [x] Браузерная проверка проходит путь пустое состояние → заполнение формы → черновик; HTTP-проверки подтверждают ограничения данных и сброс состояния при новом запуске. `mise run check` проходит, Go-тесты выполняются с `-race`.
