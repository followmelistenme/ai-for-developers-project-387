# 04: Подтверждение встречи

Status: ready-for-agent
State: closed

**Source:** [MVP сервиса бронирования звонков](../../booking-mvp/spec.md).

**What to build:** гость сообщает согласованные данные и подтверждает
выбранное время, видит результат успешной записи, а владелец видит встречу
в общем списке. Занятое время исключается для всех типов; конкурентная
попытка получает конфликт и обновлённые слоты.

**Blocked by:** 03: [«Выбор свободного слота»](03-select-free-slot.md).

- [x] Гость проходит полный путь с главной до подтверждения; поля гостя, их проверка, способ связи участников и содержание результата точно следуют итоговой спецификации.
- [x] Встреча содержит тип, дату, время начала и окончания и согласованные сведения о госте. Общий список владельца показывает встречи всех типов с согласованными полями, сортировкой и правилом учёта начавшихся встреч.
- [x] При подтверждении бэкенд заново проверяет существование и публикацию типа, актуальное окно записи, рабочие часы, сетку стартов, длительность и пересечения; обход интерфейса не обходит ограничения.
- [x] Проверка пересечений и сохранение выполняются в одной критической секции общего хранилища. Интервалы учитываются как [начало, конец); соседние встречи допустимы, полные, частичные, вложенные и межтиповые пересечения запрещены.
- [x] Из конкурентных пересекающихся запросов успешен только один. Проигравший получает согласованный ответ о конфликте и обновлённые слоты; интерфейс позволяет выбрать доступный интервал.
- [x] После успешного бронирования соответствующие интервалы исключены из доступности всех типов; выбранный ранее слот не гарантирует успеха подтверждения.
- [x] Контактные данные раскрываются только согласно согласованным представлениям; публичная доступность слотов не выдаёт несогласованные сведения о встречах.
- [x] Согласованные операции и ошибки описаны в контракте, обе стороны обновлены генерацией; интерфейс и серверная валидация согласованы.
- [x] Браузерный сценарий проверяет реальное создание встречи, список владельца и изменение доступности другого типа. HTTP-проверки с управляемым временем подтверждают все временные ограничения, соседство и пересечения, а также единственного победителя конкурентных запросов.
- [x] Новые экраны сохраняют стиль и мобильную доступность; `mise run check` проходит, Go-тесты выполняются с `-race`.

## Answer

Реализовано в `codex/booking-draft-integration`, коммит `f9f5fe4`
(`Add meeting confirmation and owner list`).

- Гость проходит путь с главной до подтверждения с именем и email;
  сервер проверяет и нормализует оба поля. Успех показывает тип,
  московскую дату/интервал, контакты и копируемую демонстрационную ссылку
  из константы `http://localhost/event/{event_id}` с ID встречи.
  Сведения предлагается сохранить самостоятельно.
- `confirmMeeting` возвращает HTTP 201 с созданной встречей, HTTP 400
  с ошибками полей или интервала, HTTP 404 для неизвестного/неопубликованного
  типа, HTTP 409 с сообщением и актуальной доступностью выбранной даты.
  Контракт изменён первым, Go и TypeScript сгенерированы.
- Общее хранилище защищает проверку типа, календарных правил, пересечений
  и сохранение одной критической секцией. Интервалы `[начало, конец)`,
  соседство разрешено, занятость общая для всех типов. Публичные слоты
  и конфликт не раскрывают контакты гостей.
- `listOwnerMeetings` и `/owner` показывают будущие и идущие встречи
  всех типов, пока окончание позже текущего времени, ближайшие сверху.
  Есть пустое состояние, загрузка, ошибка, ручное обновление и обновление
  при возврате фокуса/видимости. Контакты доступны владельцу без авторизации
  согласно согласованным ограничениям проекта.
- Конфликт сбрасывает выбранный слот, сохраняет контакты и позволяет
  выбрать другой интервал. Ожидание ответа и успешное подтверждение
  защищены от фонового обновления слотов. Неизвестный результат сети
  не выдаётся за отсутствие встречи; расширенные повторы и восстановление
  остаются задачей 05.
