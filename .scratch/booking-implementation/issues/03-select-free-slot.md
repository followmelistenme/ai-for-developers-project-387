# 03: Выбор свободного слота

Status: ready-for-agent
State: closed

**Source:** [MVP сервиса бронирования звонков](../../booking-mvp/spec.md).

**What to build:** гость открывает опубликованный тип встречи, выбирает
дату и свободный слот с учётом московского времени, окна записи,
рабочих часов и длительности. Выбор пока не создаёт встречу.

**Blocked by:** 02: [«Публикация и выбор типа»](02-publish-and-select-type.md) — завершена.

## Границы третьего среза

- Прямой запрос пользователя продолжает реализацию по узким срезам;
  согласованные правила времени достаточны для этой задачи. Итоговое
  согласование остальных сценариев MVP не блокирует её.
- Расширение контракта: `GET /api/meeting-types/{meetingTypeId}/slots`
  с необязательной календарной датой `date` в формате YYYY-MM-DD;
  без даты сервер выбирает первый день текущего окна записи.
  Черновик и неизвестный тип — HTTP 404, неверная дата или выход
  за окно записи — HTTP 400.
- Успешный ответ содержит часовой пояс, текущее серверное время,
  границы окна записи, выбранную дату и интервалы начала/окончания слотов.
  Времена передаются как RFC 3339; интерфейс явно отображает их по Москве.
  Поле `nextWindowUpdate` сообщает серверный момент следующего сдвига окна
  для обновления интерфейса без локальных календарных вычислений.
- Переключение даты сбрасывает выбранный слот. Перезагрузка страницы
  или повторный вход на тип начинают выбор заново; выбор не резервирует
  время. При сдвиге окна и повторном получении данных устаревший выбор
  очищается. Подтверждение и ввод сведений гостя пока не добавляются.
  Повтор после сетевого сбоя и возврат фокуса сохраняют запрошенную дату;
  сброс на серверное значение по умолчанию выполняется при выходе за окно.
- Проверки остаются на согласованных границах HTTP API с управляемым
  временем и браузера с настоящим API. Тестовое время задаётся через
  конструктор приложения; производственный HTTP API и окружение
  не получают механизмов подмены текущего времени.
- Состояние берётся из общего хранилища процесса. Встречи ещё нельзя
  создать: исключение занятого времени реальными бронированиями проверяется
  и дополняется в следующем срезе, без фиктивных встреч и reset-эндпоинтов.

- [x] Экран получает доступные слоты выбранного опубликованного типа через API и показывает выбранные дату, начало и окончание по Москве.
- [x] Расчёт использует Europe/Moscow независимо от окружения; окно включает завтра и сегодня + 14 дней, исключает сегодня и более поздние даты и сдвигается в московскую полночь.
- [x] Рабочие часы ежедневно 09:00–18:00; вся встреча помещается в них. Начала идут с шагом 30 минут от 09:00 при любой разрешённой длительности.
- [x] Например, слот на 30 минут в 17:30 разрешён, на 45 минут в 17:30 исключён; длительность 15 минут не создаёт начало в 09:15.
- [x] Сервер проверяет параметры запросов, существование и публикацию типа; интерфейс обрабатывает загрузку, отсутствие слотов, сетевую ошибку и устаревший выбор по итоговой спецификации.
- [x] Навигация, прямое открытие, перезагрузка и сохранение либо сброс выбора соответствуют согласованным переходам. Выбор не резервирует время и не показывает ложного подтверждения встречи.
- [x] Контракт и генерируемые типы обновлены; расчёт доступности учитывает общее хранилище. Проверка уже занятого времени реальными бронированиями дополняется задачей подтверждения встречи.
- [x] Браузерный сценарий проверяет выбор даты и интервала; серверные проверки с контролируемым временем охватывают полночь, обе границы окна, рабочие часы, длительности и шаг стартов.
- [x] Экран русскоязычный и доступен на телефоне; `mise run check` проходит, Go-тесты выполняются с `-race`.

## Answer

Реализовано в ветке `codex/booking-draft-integration`:

- `e7ef5e1` — API и интерфейс выбора свободного слота, серверные правила
  календаря и фиксируемый источник времени для проверок.
- `ae0b7e4` — сохранение запрошенной даты при ошибке, повторе и возврате
  фокуса, с регрессиями для обоих сценариев замечания ревью.

Добавлен `listAvailableSlots`: HTTP 200 содержит серверное время,
`nextWindowUpdate`, Europe/Moscow, границы окна, выбранную дату
и интервалы в RFC 3339. HTTP 400 с `fields.date` обрабатывает неверную
или вышедшую из окна дату; черновик и неизвестный тип возвращают HTTP 404.
Контракт обновлён первым, обе стороны сгенерированы закреплёнными командами.

Расчёт вынесен из HTTP в модуль доступности, а данные опубликованного типа
берутся из общего защищённого хранилища. Именованный московский часовой пояс
встроен в Go-бинарник; часы фиксируются один раз на запрос. Рабочие 09:00
и 18:00 конструируются как календарное время, включая исторические даты
смены московского смещения. Встреч ещё нет: исключение реально занятого
времени добавляется при реализации подтверждения встречи.

Интерфейс показывает дату, сетку интервалов и выбранные начало/окончание
по Москве, явно сообщает об отсутствии резервирования. Обработаны загрузка,
ошибка, повтор, пустой ответ, недоступный тип, быстрая смена дат, возврат
фокуса, обновление и московская полночь. Устаревшая дата сбрасывается
на первый день нового окна; перезагрузка и повторный вход очищают выбор.

TDD: зафиксированы падения до реализации API/поля даты, обработки неверных
дат, метаданных сдвига окна и регрессий исторического смещения и повторов
даты. Проверки на границах HTTP с управляемыми часами охватывают оба края
окна, московскую полночь на том же сервере, смену года, високосный день,
рабочие часы, четыре длительности, шаг стартов и отсутствие резервирования.
Браузер проверяет основной сценарий с настоящим API и отдельные граничные
