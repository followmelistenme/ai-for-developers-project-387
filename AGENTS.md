# Repository Guidelines

## Назначение и структура

Учебный сервис бронирования звонков. Требования и установка — в `README.md`.
Один владелец календаря; авторизация и внешние календари вне текущего объёма.

- `backend/` — Go-модуль, сервер Gin и общее хранилище календаря в памяти.
- `backend/.golangci.yml` — Go-линтеры и форматирование.
- `frontend/src/` — React, TypeScript, Vite, Tailwind CSS; алиас `@/`.
- `frontend/src/components/ui/` — компоненты shadcn/ui.
- `frontend/e2e/` — Playwright-тесты.
- `mise.toml`, `hk.pkl` — версии инструментов и общие проверки.

## Архитектура

### REST API и OpenAPI

- Используйте Gin и проектируйте API через контракт TypeSpec
  в `api/main.tsp` и `api/models.tsp`. При изменении контракта
  запускайте `mise run generate` для OpenAPI, Go и SDK.
  Решение о цепочке генерации — в `docs/adr/0003-typespec-contract.md`.
- Генерируемый OpenAPI: `api/openapi.yaml`.
- Генерируемый сервер: `backend/internal/api/api.gen.go`.
- Генерируемый клиент: всё дерево `frontend/src/api/generated/`,
  включая `sdk.gen.ts`, `types.gen.ts` и Fetch-клиент.
- Проверяйте все три артефакта командой `mise run api-check`.
  Проверка входит в `mise run check` и CI и выполняется во временной директории.
- Для Go используйте oapi-codegen: `models`, `gin-server`, `strict-server`
  и `embedded-spec`.
- Для TypeScript используйте Hey API; обращайтесь к API через
  сгенерированные SDK-функции с транспортом Fetch.
- Задавайте стабильные `operationId`, именованные схемы в `components/schemas`,
  описания и ожидаемые ошибки. DTO запросов и ответов генерируйте из контракта.
- Фиксируйте версии генераторов, коммитьте сгенерированные файлы
  и проверяйте их актуальность в CI. Сгенерированный код вручную не редактируйте.
- Подключайте валидацию входящих запросов по OpenAPI отдельно:
  `strict-server` и TypeScript-типы не заменяют её.
- Предоставьте `/openapi.json`, `/openapi.yaml` и документацию `/docs`.
- Отделяйте транспортные DTO и HTTP-обработчики от бизнес-правил и хранения данных.

### Базы данных

Поскольку проект учебный, храните все данные в памяти приложения.
После перезапуска бэкенда данные сбрасываются. Внешние БД, ORM и миграции
в текущем объёме не нужны.

Защитите общее состояние от конкурентного доступа. Проверку пересечений
и сохранение бронирования выполняйте в одной критической секции.
Хранилище общее для всех типов встреч в пределах процесса бэкенда.

### Правила бронирования

- Часовой пояс — `Europe/Moscow` независимо от окружения.
- Окно записи — с завтрашнего дня по сегодня + 14 дней включительно.
- Рабочие часы — ежедневно 09:00–18:00; встреча помещается целиком.
- Шаг стартов — 30 минут; длительность определяется типом встречи.
- Интервалы — `[начало, конец)`; соседние встречи допустимы.
- Любые пересечения между всеми типами встреч запрещены.
- При конкурентных пересекающихся запросах успешен только один;
  проигравший получает сообщение о конфликте и обновлённые слоты.

Проверяйте ограничения на бэкенде.

## Локальный запуск и Docker

Бэкенд и фронтенд должны запускаться локально и в Docker.
При реализации добавьте Dockerfile для каждого сервиса и Docker Compose
для совместного запуска. Порты и адрес API настраивайте через окружение;
обеспечьте доступность сервисов из контейнеров. Команды и переменные
документируйте в `README.md`.

Локальный запуск — `mise run backend` и Vite; совместный Docker-запуск —
`docker compose up --build`. Контейнерная приёмка — `mise run docker-check`.

## Команды разработки

Из корня: `mise trust`, `mise install`, `mise run hooks`.

- `mise exec -- npm --prefix frontend ci` — установка зависимостей.
- `mise exec -- npm --prefix frontend run test:install` — установка Chromium.
- `mise exec -- npm --prefix frontend run dev` — Vite, порт 5173.
- `mise exec -- npm --prefix frontend run build` — типизация и сборка.
- `mise exec -- npm --prefix frontend run lint` — ESLint.
- `mise exec -- npm --prefix frontend test` — Playwright; порт 4173 свободен.
- `mise run fix` — форматирование Go.
- `mise run check` — все проверки, обязательные перед завершением.

Go-проверки выполняются в `backend/`.

## Стиль и тестирование

Go: gofmt, табуляция, тесты `*_test.go` с `TestXxx`;
запускайте `mise exec -- go test -race ./...` из `backend/`.
TypeScript: два пробела, двойные кавычки, без точек с запятой;
React-компоненты — PascalCase. Соблюдайте ESLint, React Hooks и доступность.

Добавляйте тесты изменённого поведения: границы времени, пересечения,
конкурентное бронирование. Контролируйте текущее время в тестах.
Браузерные сценарии — `frontend/e2e/*.spec.ts`; порог покрытия не задан.

## Ограничения и завершение работы

- Сохраняйте посторонние изменения в рабочем дереве.
- Не редактируйте `.github/workflows/hexlet-check.yml`: им управляет Hexlet.
- Не отключайте правила линтеров. Исключения требуют решения человека: одно правило,
  путь и причина; для безопасности — также принудительный срок окончания.
- Синхронизируйте версии Node в `.nvmrc` и `mise.toml`.
- Не коммитьте секреты, `frontend/dist/` и результаты тестов.
- `mise run check` должен пройти; сообщайте о незапущенных проверках.
- Коммиты — короткие повелительные заголовки: `Add booking validation`.
- Для изменений, включаемых в выпуск, используйте Conventional Commits:
  `feat: Add booking validation`, `fix: Reject occupied slots`.
  release-please определяет версию и заметки выпуска по этим префиксам.
- В теле сообщения каждого коммита ссылайтесь на соответствующий локальный тикет:
  `Ticket: <путь к Markdown-файлу тикета от корня репозитория>`.
- В PR указывайте изменения, связанные задачи, проверки и скриншоты интерфейса.

## Agent skills

### Issue tracker

Задачи и спецификации ведутся в локальных Markdown-файлах в `.scratch/`.
Храните спецификации и тикеты в Git и отправляйте вместе с реализацией
в удалённую ветку: ссылки `Ticket:` должны открываться в её checkout.
Перед работой с задачами читайте `docs/agents/issue-tracker.md`.

### Triage labels

Используются пять стандартных triage-статусов.
Перед разбором задач читайте `docs/agents/triage-labels.md`.

### Domain docs

Единый доменный контекст: `GLOSSARY.md` и `docs/adr/`.
Перед исследованием кода читайте `docs/agents/domain.md`.
