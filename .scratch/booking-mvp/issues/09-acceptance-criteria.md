## Question

Опирается на решения
[об экранах владельца](04-owner-experience.md),
[пути гостя](05-guest-experience.md),
[API](06-api-semantics.md),
[границах модулей и атомарности](07-booking-boundaries.md)
и [локальном запуске и Docker](08-local-and-docker-runtime.md).

Какова достаточная матрица приёмки согласованного поведения и на каких
границах его проверять: бизнес-логика, HTTP API, браузер и запуск сервисов?

Связать требования с наблюдаемыми результатами. Включить московскую
полночь независимо от часового пояса окружения, обе границы окна записи,
рабочие часы, шаг стартов и длительности; соседние, частичные и межтиповые
пересечения; конкурентные запросы с единственным победителем и обновлением
слотов проигравшему. Текущее время в тестах контролируется.

Включить выбранную семантику повторов, жизненный цикл типов, контакты,
пустые состояния и ошибки, мобильную навигацию, запуск локально и в Docker,
сброс данных, публикацию OpenAPI и актуальность генерации.
Обязательные проверки AGENTS.md, включая `mise run check` и Go `-race`,
сохраняются. Определить необходимые примеры данных и ожидаемые результаты.

Результат — критерии готовности и распределение проверок без написания
тестов приложения. Новые продуктовые противоречия вынести в задачи карты.

## Comments

### 2026-11-15 — контейнерная часть приёмки восьмого среза

Для запрошенной задачи 08 сохранены ранее согласованные публичные границы:
HTTP и настоящий браузер. Контейнерный вариант запускается отдельно от
41 обычного Playwright-сценария: `mise run docker-check`, также отдельный job
Quality CI. Обычные Go `-race`, линтеры, типизация/сборка и генерация остаются
в `mise run check`.

Три контейнерных сценария проверяют чистое состояние и единый origin API/
документации, прямые маршруты и перезагрузку, создание → публикацию → запись →
список владельца, московские даты/время при UTC контейнеров и другом поясе
браузера, сброс типов/встреч/попыток после перезапуска, недоступность старых
ссылок, переподключение после пересоздания API и изменение runtime API_TARGET
без пересборки. Используются собранные образы без перехвата HTTP в локальный
API, отдельный проект и свободные порты; выполняется очистка после успеха
и ошибки. Команды воспроизводимы из README.

Общая матрица всех требований MVP и обзор карты не закрываются автоматически
этой частичной записью.
