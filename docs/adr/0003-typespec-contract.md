# TypeSpec как источник контракта API

Для задания Хекслета описываем контракт в TypeSpec и выпускаем из него OpenAPI 3.0.
Это решение заменяет выбор редактируемого YAML в [ADR-0001](0001-openapi-contract-first.md).
TypeSpec позволяет переиспользовать схемы и описания ответов ценой дополнительного
шага генерации. OpenAPI YAML остаётся общим входом для oapi-codegen и Hey API.

`mise run generate` обновляет OpenAPI YAML, Go и SDK. Все три результата хранятся
в Git, чтобы можно было просмотреть изменения контракта в PR и собрать приложение
из checkout. CI повторяет всю генерацию во временной директории.

Генерация приводит закрытые схемы к `additionalProperties: false`, которое
корректно проверяет kin-openapi, и сохраняет целочисленные типы перечислений
для oapi-codegen. Маршруты, идентификаторы операций и HTTP-схемы сохраняют
семантику исходного OpenAPI.
