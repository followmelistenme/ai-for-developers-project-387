# Как одинаково запускать MVP локально и в Docker?

## Question

Опирается на решения
[об API согласованных сценариев](06-api-semantics.md)
и [границах модулей и атомарности](07-booking-boundaries.md).

Каковы требования к запуску фронтенда и бэкенда локально и совместно
через Docker Compose, включая адреса API и конфигурацию окружения?

Согласовать переменные, значения по умолчанию и команды запуска;
различить адреса, доступные браузеру, и имена сервисов внутри контейнерной
сети. Решить, как браузер обращается к API, как обрабатываются CORS
или проксирование и прямое открытие маршрутов интерфейса.

Учесть доступность `/docs` и обоих представлений OpenAPI, способ проверки
готовности, начальные данные и сброс данных при перезапуске процесса.
Часовой пояс календаря не должен зависеть от окружения контейнера.

Результат — согласованные требования к будущим Dockerfile обоих сервисов,
Compose и разделу README с командами и переменными. Не писать конфигурацию,
не развёртывать сервис и не добавлять требования к публичному хостингу.

## Comments

### 2026-11-15 — восьмой срез: контейнерный запуск

Пользователь запросил `implement-spec 08`. Выбраны многоэтапные Dockerfile,
Compose с проверками готовности и Nginx с единственным браузерным origin:
`/api`, `/docs`, `/openapi.json`, `/openapi.yaml` проксируются в API,
маршруты SPA открываются напрямую и после перезагрузки.

По умолчанию хостовые порты 5173/8080, `BIND_HOST=127.0.0.1`;
внутренние порты Nginx/API — 80/8080, API слушает все интерфейсы контейнера.
`API_TARGET=http://backend:8080` задаёт origin для Nginx внутри сети,
а не адрес браузера. Меняется через окружение при пересоздании фронтенда
без пересборки. Контейнеры по умолчанию используют `TZ=UTC`, календарь
остаётся московским благодаря явному IANA-поясу и встроенной базе Go.
Локальные команды и переменные продолжают работать как прежде.

Проверка контейнеров выделена в `mise run docker-check` и отдельный job
`Container acceptance` в Quality CI, обычный `mise run check` не требует
Docker Engine. Приёмка собирает образы, использует отдельный проект,
свободные хостовые порты и альтернативное имя API. Браузер проходит полный
сценарий без подмены HTTP-маршрутов; перезапуск API очищает состояние,
пересоздание API проверяет повторное DNS-разрешение Nginx. Неверный runtime
адрес даёт 502, его восстановление возвращает API и документацию без сборки.
Все собственные контейнеры, сеть и образы удаляются при любом исходе.

Это реализация запрошенного среза; общий обзор требований карты остаётся
открытым. Постоянное хранение, авторизация и публичное развёртывание
не добавляются.
