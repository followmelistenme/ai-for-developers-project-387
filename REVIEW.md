# Критерии ревью pull request

## Требования и поведение

- Сопоставьте изменение с задачей, описанием PR и критериями приёмки.
  Ищите расхождения и случаи, для которых в диффе нет подтверждения.
- Проверьте поведение в основном сценарии и на границах, затронутых диффом.
  При изменениях бронирования проверьте московское время, окно записи,
  рабочие часы, соседние интервалы и атомарность конкурентной записи.
- При изменениях интерфейса проверьте навигацию, доступность с клавиатуры,
  узкие экраны и обработку затронутых состояний загрузки и ошибок.

## Контракт, безопасность и сопровождение

- При изменении API проверьте `api/openapi.yaml`, валидацию запросов,
  документированные ошибки и синхронизацию сгенерированных сервера и SDK.
- Ищите утечки контактов и секретов, лишние привилегии и пути, по которым данные
  пользователя могут стать командами или исполняемой разметкой.
- Проверьте, что тесты покрывают изменённое поведение и ключевые критерии
  приёмки. Для изменений CI проверьте событие, фильтры, права, ограничения
  вызова модели и публикацию результата для актуальной версии PR.

## Результат

- Оставляйте до пяти конкретных замечаний с путём к файлу и номером строки,
  если строку можно установить по диффу. Для каждого укажите условие возникновения
  и последствие для пользователя, API или процесса доставки.
- `high` означает потерю данных, существенную проблему безопасности или поломку
  основного сценария. `medium` означает воспроизводимую регрессию либо пропуск
  критерия приёмки. `low` означает локальную проблему с конкретным последствием.
- Учитывайте только видимое в диффе и описании PR. Отмечайте пробелы в проверках
  только при наличии доказательств и не утверждайте, что запускали тесты.
