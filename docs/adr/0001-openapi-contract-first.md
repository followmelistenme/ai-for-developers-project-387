# Общий OpenAPI-контракт для Go и TypeScript

Для бэкенда и фронтенда нужны согласованные типы запросов и ответов,
поэтому источником истины выбран `api/openapi.yaml`: Go DTO и серверный
интерфейс генерирует oapi-codegen для Gin, TypeScript-типы —
openapi-typescript для клиента openapi-fetch.
Это заменяет ранее выбранные chi + Huma и генерацию спецификации из Go-кода:
контракт можно проектировать до реализации обеих сторон, ценой поддержки YAML
и двух закреплённых генераторов с проверкой актуальности результатов в CI.

## Последствия

Клиентская часть решения заменена в [ADR-0002](0002-generated-client-sdk.md):
вместо openapi-typescript/openapi-fetch генерируется SDK Hey API.

- Сгенерированные файлы коммитятся в Git; изменения вносятся через контракт.
- Для oapi-codegen используются `models`, `gin-server`, `strict-server`
  и `embedded-spec`.
- Валидация запросов по схеме подключается отдельно; сгенерированные типы
  не заменяют проверку ограничений данных во время выполнения.
- Правила бронирования и хранение в памяти приложения остаются
  вне сгенерированного транспортного слоя.
- Решение принято; контракт и настройка генерации будут добавлены
  при реализации API.
